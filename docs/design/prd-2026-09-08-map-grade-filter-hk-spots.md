## 1. 背景与问题(Problem,不是方案)

现状(来自项目调研):

1. 地图页 `Map/map.html` 硬编码 **15 个攀岩点**,首页 `index.html` 另有一份简化副本(只有坐标),**两处重复维护**,新增点要改两处。
2. 难度字段 `diff` 是**非结构化字符串**,格式混用:"VB - V12"、"V0 - V7+"(V 级)、"F4 - F8A+"、"F2B - F8B"、"F5 - F7C+"(法国级)、"Top Rope"、"Top Rope/Lead"(纯文本)。用户只能靠搜索框文本子串匹配,**无法按难度等级筛选**。
3. 收录不完整:香港主要攀岩区域远不止 15 个。
4. 项目是**纯静态、零构建、零测试、零 CI** 的网站,没有任何数据校验手段,数据会随改随坏。
5. 项目没有数据维护流程,也没有说明"新增一个攀岩点该怎么改、改完怎么验证"。

## 2. 目标

1. **目标 1 — 难度筛选**:用户可在地图页按难度等级(VB–V14)筛选抱石点,并与现有类型筛选、关键词搜索叠加。
2. **目标 2 — 全量数据**:数据收录从 15 个扩展到香港主要攀岩区域全量,以权威公开源为基准、人工整理入库。
3. **目标 3 — 维护方案**:单一数据源 + 校验脚本 + 自动化测试 + CI + 中文维护文档 + GitHub Issue/PR 社区纠错通道 + 定期人工核对流程。

## 3. 范围

### 在范围内

- 难度筛选 UI(地图页,中英双语)
- 难度字段结构化(抱石 V 级、攀登法国级)
- 单一数据源 `js/spots-data.js`,地图页与首页共用
- 全量数据:以 theCrag 香港区为基准清单、hongkongclimbing.com 指南为复核,人工整理入库
- 校验脚本、单元测试、QA 用例、GitHub Actions CI
- 中文维护文档、README 更新

### 不在范围内(越界有真实成本)

| 项目 | 不在范围内的理由 |
| --- | --- |
| 攀登点(法国级)的筛选按钮 | 法国级转 V 级无公认换算标准,本次只结构化法国级数据,不做其筛选 UI(为未来扩展留好数据) |
| 单条线路(route)级别的数据 | 本网站地图粒度是「攀岩点/区域」;收录全部线路需重建整个数据模型 |
| 站内提交表单/审核后台 | 纯静态站无后端;改用 GitHub Issue/PR 流程 |
| 复制 theCrag / hongkongclimbing.com 的描述文本 | 版权不许可;只取事实性字段(名称/坐标/难度/类型),描述自撰双语 |
| 修复 Google Maps API key 明文暴露 | 既有问题、与本次功能无关,建议另行处理 |

## 4. 语言与技术栈(已实测)

- **运行方式不变**:纯静态,无构建,不新增任何运行时依赖(Google Maps JS API 为既有依赖)。
- **新增零依赖 Node 工具链**:Node v22.18.0(已实测),测试用 Node 内置 `node --test`,不引入任何 npm 包,无需 `npm install`。
- **数据文件用 JS 模块而非 JSON**:因为用户可能以 `file://` 直接打开页面,浏览器会拦截 `fetch` 本地 JSON,而 `<script src>` 不受影响。导出用 UMD 风格:浏览器得到全局变量、Node 测试可 `import`。
- **测试命令**:`npm test`(= `node --test tests/`);**数据校验命令**:`npm run validate`;QA 用例用 `node qa/run-all.mjs`(Windows 友好,不用 bash)。

## 5. 功能需求

### F-1 难度筛选(任务 1)

- 地图页筛选条新增一行「难度 V 级」按钮:`全部 / VB / V0 / V1 / … / V14`(单选,小尺寸按钮,移动端自动换行)。
- 语义:**选 Vn → 显示难度区间包含 Vn 的抱石点(NB/AB)**;攀登点(NC/AC)无 V 级,难度筛选激活时隐藏。
- 与类型筛选、关键词搜索**叠加(AND)**。
- "+" 档位归入其基础档:如 "V7+" 算作区间包含 V7;"VB" 为独立档。
- 双语标签(「難度」/「Grade」),沿用现有 `langDict` + `data-lang-key` 机制。

### F-2 难度字段结构化

- 每个点的难度从字符串改为结构化对象:
  - 抱石:`grades: { boulder: { min: "VB", max: "V12+" } }`
  - 攀登:`grades: { rope: { min: "F4", max: "F8A+" } }`
  - 无结构化难度(如「Top Rope/Lead」):`grades: null`,难度筛选时视为无 V 级
- 展示文案由结构化字段生成,与原文案一致(如 "VB - V12")。
- 解析规则:V 级序 VB < V0 < V1 < … < V14,后缀 "+" 视为基础档 + 0.5;法国级按标准序(F4、F5、F6A、F6A+、…、F8B+)。

### F-3 单一数据源

- 新建 `js/spots-data.js`(UMD 风格),内含全部点数据。
- `Map/map.html` 改为 `<script src="../js/spots-data.js">`、`index.html` 改为 `<script src="js/spots-data.js">` 加载,删除各自内联 `spots` 数组。

### F-4 全量数据(任务 2)

- 以 **theCrag 香港区**为基准清单(事实性字段:名称、坐标、难度、类型),以 **hongkongclimbing.com** 指南为复核补充(中文名称、交通、最新区域)。
- 目标:覆盖基准清单中全部主要区域,**预计 30–50 个点**(含室内馆);完整性以「快照对照零缺失」为硬标准(见 F-5)。
- 每点字段:`id`、`typeCode`(NB/AB/NC/AC)、`lat`、`lng`、`grades`(F-2)、`name{zh,en}`、`desc{zh,en}`、`trans{zh,en}`、`gmap`(外链)、`source`(数据来源 URL,维护追溯用)。
- 描述与交通文案**自撰双语**,不复制受版权文本。
- 生成 `data/thecrag-hk-areas-snapshot.json`:基准区域清单快照(名称 + 来源 URL),人工核对后入库。

### F-5 维护方案(任务 2)

- **校验脚本** `tools/validate-spots.mjs`(Node 运行):id 唯一;坐标在香港范围(lat 22.1–22.6、lng 113.8–114.5);类型码合法;双语字段齐全;难度格式合法;区间 min ≤ max;**对照快照输出缺失区域清单**。
- **维护文档** `docs/spots-data-guide.md`(中文):字段表、新增/修改点的步骤、坐标获取方法、难度格式规范、**每半年人工核对 theCrag 与 hongkongclimbing.com 的流程**。
- **CI** `.github/workflows/ci.yml`:push/PR 自动跑 `npm test` + `npm run validate`。
- **社区纠错通道**:README 与维护文档写明 GitHub Issue/PR 流程。

## 8. 风险与开放问题

1. theCrag 无免费全量导出,数据需人工整理;已按版权边界只取事实性字段、描述自撰。
2. 坐标精度:区域级坐标即可(与现状一致),不要求单线路坐标。
3. Google Maps API key 明文暴露:既有问题,不在本次范围,建议用户后续单独处理。
4. theCrag 页面可能限制自动抓取;若脚本抓不到清单,改为人工逐页核对录入,标准不变(快照对照零缺失)。
